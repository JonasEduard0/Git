				Git
Workspace: O computador.

Staging Area(index): Caixa onde separa as páginas que quer oficializar. Escreveu 10 linhas mas 5 ficaram boas. Coloca essas 5 na caixa.

Repositório Local (HEAD): Onde ficam guardadas as versões oficiais localmente.

Repositório Remoto: Onde ficam versões na Nuvem(GitHub).

git --version				     | Versão do git.
git config --global user.name "Seu Nome"     | Quando em equipe, todos sabem quem alterou.
git config --global user.email "a@gmail.com" | Cadastra email pra se identificar.
git config --global --list		     | Printa suas informações.

git clone link repos 	| Clona o repositório no pc e permite as alterações.
cd pasta-repositorio 	| Entra na pasta do repositório.
git add a.html       	| Coloca o arquivo do Workspace na Staging Area.
git add .	        | Adiciona todos arquivos não adicionados ao Staging Area.
git commit -m "txt"  	| Salva oficialmente no repositório local.
git push     	     	| Envia pro GitHub/Nuvem.
git pull     	     	| Puxar a versão atual do projeto do repositório remoto.
git checkout a1b2c3d	| Volta pra versão do código. main: volta ao presente(última versão).
git status	     	| 
git log		     	| Histórico de commits. --oneline: resumido.
git reset --soft HEAD~1 | Desfaz último commit (ainda não deu push), mas arquivos permanecem editados.
git reset --hard HEAD~1 | Desfaz e descarta mudanças.


			Explicações
Commit: Versão salva.

	Ignorar Arquivos
Crie arquivo .gitignore na raiz do projeto. Ignora esses arquivos/pastas. Nunca vai commitar.

	Após git clone
Dentro da pasta há o arquivo README.md e uma pasta oculta .git, que cuida das versões do sistema. 
Esta pasta está vinculada ao repositorio remoto.

	Problema
Esquece de dar git pull antes de trabalhar. Trabalhou em versão antiga e quando tenta git push, dá erro. Tem que dar git pull, Git mescla(merge) as mudanças e se não tiver conflito, ok, se tiver(você e alguem mexeram na mesma linha), Git marca no arquivo e você decide qual versão manter. Edita manualmente, salva, commita.

	Boas práticas
Começar no imperativo, ser específico. "Corrige validação de email no formulário".
Se precisar descrição muito detalhada: git commit -m "Titulo" -m "Descricao grande".
Faça um commit por tarefa, evitar fazer muita coisa e commitar.

	Branch
git checkout -b novo-design | 
Branch: Linha do tempo paralela. Quer testar algo mas não quer quebrar o site funcionando. Cria branch novo-design, trabalha lá. Se ficar bom, mescla(merge) com main. Se ficar ruim, deleta a branch.
